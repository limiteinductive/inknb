# Interface review, October 16

Five agents independently reviewed pointer handling, pane layout, navigation and focus, the native host, and build delivery. Each review was read-only.

## Findings

| Finding | Evidence | Change |
| --- | --- | --- |
| A resize could persist the previous width. | The layout callback ran before the updated panel width reached the DOM. | Persistence derives pixels from the callback's new layout. |
| Native file drag handling could intercept sidebar reordering. | Tauri enabled its native drag handler. Wry returned handled before WebKit received the drag operation. | The web view disables native file drag handling. React Aria owns internal document dragging. |
| The preview divider had an incomplete hit area beside HTML content. | Its physical width was one pixel. The calculated target extended into a separate iframe. | A physical thirteen-pixel target surrounds a one-pixel line. Pointer capture starts on press. |
| Controlled navigation selection ignored row selection changes. | The grid received selected keys without a corresponding change handler. Default action behavior also depended on selection mode. | Replacement selection, selection changes, and row actions route to document navigation. |
| Grid focus could inherit the external global outline. | The global React Aria selector had higher specificity than the grid reset. | Grid, row, and document-button focus use explicit one-pixel inset outlines. |
| Aside placement could remain stale after resizing. | Rail updates observed scrolling and window changes, but missed editor geometry changes. | An editor observer recomputes passage placement. |
| Previous evidence did not establish pointer correctness. | Keyboard input and screenshots did not exercise a pointer gesture. | Verification records retain gesture-specific evidence and explicit limits. |

These findings do not establish a single cause for every reported pointer failure. The native drag finding concerns document reordering. The iframe finding concerns preview hit testing.

## Current implementation

React Resizable Panels owns pane sizing, pointer movement, constraints, keyboard behavior, and accessibility state. A shared library record stores the preferred preview width after user interaction.

The group restores that preference when its available space changes. It does not persist temporary constraints. Fullscreen retains the preferred width. The editor keeps its existing instance and Undo history.

The UI inspector exposes control roles, focus styling, ARIA state, and recent divider pointer events. The event trace resets for each press. Capture observations describe that event phase.

## Evidence

Installed build: `0.5.1+52acd0e24375`.

- TypeScript and all nineteen existing frontend tests passed.
- Prettier and the diff whitespace check passed.
- The production bundle passed local signature verification.
- Native keyboard input changed the preview width from 580 pixels to 533.25 pixels.
- The persisted preferred width was 533.2492 pixels.
- Native fullscreen entry and Escape restored the resized preview.
- The separator exposed a thirteen-pixel physical target and an enabled accessibility state.
- The three existing documents retained their complete text, metadata, and selections through installation.

Automated pointer input still fails before delivery to the web view. Native control reports `noWindowsAvailable`. The divider trace contains no pointer event from those attempts.

The first resize build failed the human pointer check. The subsequent library-only build also failed that check. Neither result validates the final reviewed build.

The final build still needs native pointer verification for preview resizing and document reordering. HTML crossing, narrow-window behavior, and pointer cancellation also remain unverified in this build.
